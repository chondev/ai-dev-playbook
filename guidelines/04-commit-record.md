# 04. 커밋·기록 단계 지침

- 적용: 커밋 준비·실행, 커밋 메시지 초안, 이슈 트래커·문서 기록
- 상위 지침: [`../AGENTS.md`](../AGENTS.md) (공통 규칙이 항상 우선. 커밋·병합·외부 문서 반영은 사용자가 명시적으로 요청한 경우에만 수행)

## 1. 형상관리(VCS) 작업 원칙

- 작업 사본의 실제 VCS 종류(Git 또는 SVN)와 브랜치·URL을 `PROJECT.md` 및 상태 명령(`git status` / `svn info`)으로 확인한다. 경로 이름만으로 추측하지 않는다.
- 트렁크/메인 동기화와 브랜치 병합은 사용자가 수행하거나 명시적으로 요청한 경우에만 보조한다.
- 브랜치 간 직접 병합을 임의로 수행하지 않는다.
- Commit 전에는 대상 파일, diff, 빌드·테스트 결과와 제외할 로컬 파일을 사용자에게 보고한다.
- Commit 여부와 메시지는 사용자가 최종 결정한다.

## 2. 커밋 준비 산출물

커밋 메시지 초안이나 커밋 준비를 요청받으면 다음 두 산출물을 함께 정리한다(초안만 작성하고 끝내지 않는다).

1. **변경 파일 diff 리포트(`.md`)**: 작업 단위별 변경 파일 목록, 목적, 검증 상태, 제외할 로컬 파일 명시
2. **작업 단위별 커밋 메시지 초안**: 프로젝트 지정 템플릿 준수

## 3. 커밋 메시지 형식

`PROJECT.md`에 별도 양식이 없다면 다음 짧은 표준 형식을 기본으로 사용한다.

- **제목**: `[TAG][SCOPE][ISSUE-ID or 이슈없음] 변경 내용 한 줄 요약`
  - `ISSUE-ID`가 없는 직접 작업은 생략하지 말고 `이슈없음`으로 명시한다.
- **본문(핵심 3줄)**:
  ```text
  목적: 왜 변경했는지 1줄
  수정 파일: 주요 대상 파일 (전체 나열 불필요 시 대표 파일 + 개수)
  검증: 실제로 확인한 방법 (정적/브라우저/키보드 등, 한 줄)
  ```
- 트렁크/메인 동기화 병합 커밋은 기존 병합 메시지 형식을 유지한다.

## 4. 인코딩 및 환경별 주의사항

Windows(로케일 CP949 등) 환경에서 커밋 메시지를 파일로 넘길 때는 콘솔 인코딩 오해석으로 인한 한글 깨짐(mojibake)을 막기 위해 반드시 UTF-8 인코딩 옵션을 명시한다.

- SVN을 사용하는 경우 세부 명령 규칙은 [`../modules/vcs-svn-windows.md`](../modules/vcs-svn-windows.md)를 따른다.

## 5. 협업 문서 및 이슈 트래커 기록

Notion·Jira 등 외부 협업 문서의 조회·작성·수정은 사용자가 명시적으로 요청한 경우에만 수행한다. 요청이 없으면 등록 가능한 초안만 제공하며 실제 외부 문서 상태를 변경하지 않는다.

다중 에이전트 협업 및 Notion·협업 문서 기록 시 수정 주체 표기, 수정 전·후 재조회 검증, 검증 상태 분리, 기록 금지 정보 기준은 [`../modules/docs-notion-sync.md`](../modules/docs-notion-sync.md) 및 [`../modules/multi-agent-and-docs.md`](../modules/multi-agent-and-docs.md)를 따른다.
