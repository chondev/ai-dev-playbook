# 02. 구현·수정 단계 지침

- 적용: 사용자가 명확히 수정·구현을 요청한 경우(구현 후에는 [`03-verification.md`](03-verification.md)도 함께 따른다)
- 상위 지침: [`../AGENTS.md`](../AGENTS.md) (공통 규칙이 항상 우선)

## 1. 기본 원칙

명확한 수정 요청이 있을 때만 구현하며(상세: `AGENTS.md` 4절 '권한과 작업 경계'), 관련 구조를 먼저 확인한 뒤 안전한 최소 범위에서 구현하고 검증한다.

## 2. 변경 절차

1. 대상 작업 사본과 기존 로컬 변경 확인
2. 관련 파일과 호출 구조 추적([`01-analysis.md`](01-analysis.md) 2절 '소스 탐색과 화면 추적'). 구현 요청이어도 이 추적 순서를 건너뛰지 않는다.
3. 실제 화면에 적용되는 템플릿·Layout·CSS·JavaScript 확인
4. 기존 공통 기능과 유사 구현 확인
5. 문제 원인, 변경 예정 파일과 영향 범위 설명
6. 필요한 파일만 최소 변경
7. diff 검토
8. 관련 정적 검사·빌드·테스트
9. 기존 기능 회귀와 요구사항(예: 접근성) 검증 구분
10. 수행 결과와 미수행 검증 보고

예상보다 범위가 크게 확장되거나 다른 작업 사본·외부 시스템 변경이 필요하면 작업을 확대하기 전에 보고한다.

## 3. 공통 구현 제약

- `PROJECT.md`에 명시된 런타임·프레임워크·브라우저 호환성 기준을 준수한다.
- 기존 아키텍처 계층(예: `Controller → Service → DAO → SQL Mapper`)과 View 구조를 존중한다.
- JavaScript는 수정 대상 파일의 기존 문법과 이벤트 처리 방식을 우선한다. 최신 문법이나 브라우저 API는 지원 환경 호환성을 확인한 경우에만 사용한다.
- 새로운 프레임워크, 라이브러리, 추상 계층을 불필요하게 도입하지 않는다.
- 요청 목적과 무관한 코드 정리나 리팩터링을 함께 수행하지 않는다.
- **멀티라인 목록 선행 콤마 규칙**: 여러 줄로 이어 붙인 문자열·SQL 컬럼·배열 목록을 새로 작성하거나 늘릴 때는 콤마를 줄 앞에 두어 구분자 누락(두 문자열이 하나로 합쳐지는 실수 등)을 예방한다.
- **마크업 삽입 따옴표 규칙**: 기존 템플릿·JS 문자열에 HTML 태그나 속성을 넣을 때는 주변 따옴표 형식에 맞추고, 정적 문법 점검([`03-verification.md`](03-verification.md) 3절)을 수행한다.

세부 스택·도메인 규칙은 `PROJECT.md`에서 활성화한 [`../modules/`](../modules/) 문서를 따른다.

## 4. 공통 변경과 회귀 위험

다음 영역은 여러 사이트와 화면에 영향을 줄 수 있다.

- 공통 레이아웃 정의(Tiles/Layout)
- Header·Footer·GNB·LNB·퀵 메뉴·스킵 내비게이션
- 공통 CSS와 JavaScript
- 세션 타이머, Form Validator, Layer Popup, Datepicker
- CMS 스킨과 게시판 템플릿
- 로그인·인증·결제·외부 연계 모듈

공통 파일 수정 전 영향받는 사이트, Layout, 화면, 선택자, 이벤트, PC·모바일 사용 여부와 별도 담당자 변경 가능성을 확인한다.

동일 문제가 반복될 때는 개별 화면, 사이트/모듈별 공통, 전체 공통 수정의 영향과 테스트 비용을 비교한다. 가장 적은 영향으로 기준을 충족하는 방법을 선택한다.

공통으로 보이는 코드도 곧바로 전체 수정 대상으로 정하지 않는다. 조건부 분기, viewport 설정, 문서 언어 속성, 호환성 meta 태그처럼 공통 include와 정적 페이지 직접 진입 경로에 흩어져 있을 수 있는 문제는 먼저 검색으로 파일 수와 분포를 확인하고, 별도 작업 단위와 독립 커밋 후보로 관리한다.

외부 협업 문서(Notion 등) 조회는 명시적 요청이 있을 때만 하므로(`AGENTS.md` 4절), 요청이 없거나 조회할 수 없으면 로컬 기준 문서와 코드 검색으로 확인한 근거로 진행한다. 이때 외부 문서 세부 기준은 `미확인`으로 보고하고, 판단이 그 기준에 달려 있으면 작업을 확대하기 전에 사용자에게 확인을 요청한다.
