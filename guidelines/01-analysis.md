# 01. 분석·진단 단계 지침

- 적용: 분석·설명·검토·진단 요청, 수정 전 원인 파악
- 상위 지침: [`../AGENTS.md`](../AGENTS.md) (공통 규칙이 항상 우선)

## 1. 분석 요청에서 수행할 일 (읽기 전용)

- 관련 파일과 호출 구조 탐색
- 현재 구현과 문제 원인 파악
- 공통 코드와 개별 화면 영향 구분
- 개선 방법과 대안 제시
- 검증 및 회귀 테스트 항목 제시
- 확인하지 못한 내용과 이유 보고

분석 요청에서는 어떤 상태도 변경하지 않고, 결과에 `소스는 수정하지 않았다`고 명시한다(상세: `AGENTS.md` 4절 '권한과 작업 경계').

## 2. 소스 탐색과 화면 추적

실제 운영·빌드 대상 소스(예: `src/main`)를 우선 확인한다. `target`, `bin`, `dist`, 백업, 임시 파일과 생성 결과물을 실제 수정 대상으로 오인하지 않는다.

웹 화면 데이터 흐름이 중요한 경우 다음 순서로 추적한다(스택에 맞게 적용).

```text
화면 URL
  → Controller / Router 매핑
  → 반환 View 또는 템플릿 이름
  → 레이아웃 정의(예: Tiles defs / Layout 컴포넌트) 및 suffix
  → Layout·Header·GNB·LNB·Footer·Body include
  → 실제 Body 템플릿과 포함 컴포넌트
  → CSS·JavaScript
  → 필요한 경우 Service → DAO/Repository → SQL Mapper → DB
```

Controller가 반환하는 View 이름만 보고 최종 화면 파일을 확정하지 않는다. 레이아웃 설정과 공통 자원 로딩 차이를 확인한다.

템플릿/JSP 등 화면 파일에서는 다음을 확인한다.

- 조건 분기와 include(정적/동적 include, attribute, slot)
- form action과 서버 전송 파라미터
- Ajax 요청 URL과 JavaScript 이벤트 바인딩
- Model, 세션, 권한에 따른 분기
- CMS·게시판 스킨과 관리자 생성 콘텐츠 여부

일부 파일만 확인한 결과를 전체 프로젝트 현황으로 단정하지 않는다. 확인 범위에 없는 계층은 `현재 확인 범위에 포함되지 않음`으로 기록한다.

다른 작업 사본을 기준으로 수행한 기존 분석을 재사용할 때는 분석 기준 경로를 명시한다. 실제 수정 전에 대상 작업 사본의 관련 파일과 diff를 확인하며, 같은 저장소에서 분기됐다는 이유만으로 파일 내용이 동일하다고 가정하지 않는다.

## 3. 관리자/CMS 생성 콘텐츠 추적

사용자 화면에 출력되는 콘텐츠가 관리자 시스템이나 CMS에서 생성되는 경우 입력부터 출력까지 추적한다.

- Controller·Service·DAO·Mapper·DB 흐름
- 파일 생성·덮어쓰기 경로
- HTML 저장과 정제(Sanitize)
- 웹 에디터 초기화와 결과 HTML
- 이미지·대체텍스트와 파일 업로드
- 허용 태그·속성, iframe, Base64 Data URI
- 저장형 XSS와 사용자 화면 출력 위험

추적 중에도 관리자 저장 동작과 생성 파일·DB는 변경하지 않는다(상세: `AGENTS.md` 4절 '권한과 작업 경계').
