# 결함 티켓 예시 · 필수 입력이 비어 있어도 제출을 시도함

[브라우저 시험 프롬프트](../prompts/unit-test-execution-prompt.md)의 기록 형식을 설명하기 위해 구성한 모의 사례입니다. 아래 값은 예시 관찰값입니다.

| 항목 | 내용 |
|---|---|
| 시험 식별자 | SYS-01-STEP-015 |
| 발생 일시 | YYYY-MM-DD 14:22:10 (Asia/Seoul, 예시) |
| 환경 | Playwright Chromium, 백엔드와 연결하지 않은 로컬 모의 신청 폼 |
| 화면 URL | `http://localhost:8080/apply/form.do` (모의 경로) |
| 시험 조건 | 모의 화면을 열기 전에 제출 경로의 요청을 브라우저에서 가로채 중단하도록 설정 |
| 조작 | 연락처를 비워 둔 채 모의 폼에서 제출 동작 실행 |
| 기대 결과 | 연락처 입력 안내 표시, 해당 필드로 초점 이동, 제출 요청 시도 0회 |
| 관찰 결과 | 안내가 표시되지 않고 초점은 제출 버튼에 남음. 제출 경로로 향하는 POST 요청 1회를 브라우저에서 중단 |
| 판정 | **Fail**. 필수값이 비었는데도 클라이언트 검증이 제출 시도를 막지 못함 |

### 증거 자료

- **화면 캡처** — 조작 직후의 화면을 기록합니다. 예시 파일명은 `screenshots/SYS-01-STEP-015_Fail.png`이며, 이 모의 티켓에는 이미지를 첨부하지 않았습니다.
- **콘솔 오류 로그** — 미수집. 오류 발생 여부는 미확인입니다.
- **네트워크 관찰** — 제출 경로로 향하는 POST 요청 시도 1회. 브라우저에서 요청을 가로채 중단한 시점까지를 판정 근거로 삼았습니다.

### 후속 확인

구현자는 폼의 `onsubmit` 처리기가 빈 필드에서 동기적으로 `false`를 반환하는지 확인합니다. 수정 후 같은 모의 조건에서 안내 문구, 초점 위치, 제출 시도 횟수를 다시 확인합니다. 서버 응답과 DB 저장 여부는 이 시험의 관찰 범위 밖입니다.
