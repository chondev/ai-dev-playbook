# [템플릿] 웹 사이트 분석 기반 테스트 시나리오 엑셀 자동 생성 작업 프롬프트

아래 지침을 따라 대상 웹 사이트의 화면을 브라우저 자동화(또는 DOM 분석)로 탐색하고, 기능별 테스트 시나리오를 체계적으로 도출하여 표준 엑셀(Excel) 문서로 자동 작성하라. 기존에 사용 중인 **샘플/템플릿 엑셀 파일이 제공되는 경우, 해당 파일의 헤더 구조·열 배치·서식·문장 표현 스타일을 최우선으로 학습하여 동일한 형식으로 작성**한다.

---

## 0. 실행 설정 파라미터 (작업 시 사용자/작성자가 지정)

```yaml
# [1] 분석 대상 웹 사이트 정보
TARGET_SITE:
  base_url: "http://localhost:8080"
  target_urls:
    - "/main.do"
    - "/sub/index.do"
    # 필요 시 추가 URL 등록
  login_prerequisite: # 로그인이 필요한 화면 분석 시 (없으면 null)
    required: false
    login_url: "/login"
    account_env_id: "TEST_USER_ID"     # 환경변수로부터 계정 주입
    account_env_pw: "TEST_USER_PW"

# [2] 엑셀 샘플/템플릿 및 출력 경로
EXCEL_CONFIG:
  sample_template_path: "./sample_testcase.xlsx" # 없으면 null
  output_excel_path: "./output_generated_testcase.xlsx"
  sheet_name: "단위테스트케이스"
  id_prefix: "SYS-MAIN"
  start_row: null                       # 샘플 분석 시 자동 감지

# [3] 시나리오 생성 상세 옵션
GENERATION_OPTIONS:
  granularity: "standard"               # standard / deep / smoke
  include_validation_cases: true        # 필수값 누락 등 음성(Negative) 케이스 포함
  include_navigation_cases: true        # GNB/LNB, 푸터, 바로가기 등 이동 케이스 포함
  include_popup_modal_cases: true       # 레이어 팝업 열기/닫기 케이스 포함
  include_a11y_checkpoint_tags: false   # [WA:대체텍스트], [WA:초점] 등 접근성 태그 표기 여부
  max_cases_per_page: 30                # 페이지당 최대 생성 시나리오 수
```

## 1. 엑셀 샘플/템플릿 규칙 학습 (샘플 파일이 제공된 경우)

기존 `sample_template_path` 파일이 존재하는 경우, AI 에이전트는 작성 전 반드시 다음 항목을 **우선 분석하고 동일하게 계승**한다.

1. **시트 구조 및 메타데이터 파악**:
   - 숨겨진 시트(예: 체크리스트, 코드표)가 있는지 확인하고, 실제 시나리오가 작성되는 주 시트(`sheet_name`)를 특정한다.
   - 상단 메타데이터 영역(시스템명, 작성자, 작성일, 버전 등)의 위치와 구조를 파악한다.
2. **컬럼 매핑(열 배치) 자동 감지**:
   - 헤더 행을 검색해 `스텝/ID`, `화면/기능명`, `사용자 조작 행위`, `입력값`, `예상 결과`, `선행 조건`, `결과 기록 placeholder(시험자/시험일자/결과/비고)` 열을 식별한다.
3. **문장 스타일 및 어조(Tone & Voice) 학습**:
   - 기존 샘플의 사용자 행위(`~ 버튼을 클릭한다.`) 및 예상 결과(`~ 화면으로 이동한다.`) 서술 방식을 그대로 따른다.
4. **수식 및 셀 서식 보존**:
   - 셀 병합, 글꼴, 배경색, 테두리, 수식, 데이터 유효성 검사(드롭다운 목록)를 신규 행에도 동일하게 적용한다.

---

## 2. 화면 탐색 및 인터랙션 분석 원칙

1. **실제 브라우저(Playwright 등)를 통한 화면 렌더링 검사**:
   - 원시 HTML만 보지 않고 브라우저로 페이지를 열어 렌더링된 DOM 트리와 가시성을 확인한다.
2. **탐색 시 절대 안전 원칙 (DB 쓰기 및 사이드 이펙트 금지)**:
   - **실제 '등록 확정', '삭제', '결제', '신청 제출' 버튼은 절대 최종 클릭하지 않는다.**
   - 폼 검증은 **필수값 누락 상태에서의 유효성 메시지 확인**까지만 수행하거나, 확인 팝업(Confirm)이 뜨면 **취소(Cancel)**를 누른다.
   - 실제 개인정보나 금융/인증 정보는 입력하지 않는다.
3. **컴포넌트별 분석 대상**:
   - Form 컨트롤(`<input>`, `<select>`, `<textarea>`, 체크박스, 라디오)
   - 버튼 및 인터랙션(조회/검색, 초기화, 등록/수정/삭제, 페이징)
   - 내비게이션(GNB, LNB, Breadcrumb, 탭, 배너)
   - 레이어 팝업 및 대화상자

---

## 3. 시나리오 도출 패턴 (4대 표준 유형)

1. **내비게이션 및 메뉴 이동 (NAV)**: 메뉴/링크/배너 클릭 → 대상 화면 이동 및 Title/Heading 확인
2. **조회 및 필터링 (SEARCH)**: 조건 선택·검색어 입력·검색 클릭 → 목록 및 건수 갱신 확인
3. **입력 폼 유효성 검증 (VALIDATION)**: 필수 항목 공란 제출 → 안내 메시지 표출 및 해당 입력칸 초점 이동 확인
4. **모달/팝업 및 특수 인터랙션 (POPUP)**: 팝업 열기 → 배경 비활성화·닫기/ESC 동작·호출 요소로 초점 복귀 확인

---

## 4. 엑셀 파일 작성 및 완료 보고

- Python `openpyxl` 등으로 템플릿 서식과 수식을 유지한 채 새 파일(`output_excel_path`)로 저장한다.
- 시험 결과 영역(시험자, 시험일자, 결과, 비고)은 실행 전이므로 공란 또는 기존 수식을 유지한다.
- 완료 시 **참조한 샘플 구조, 분석한 URL 수, 도출된 시나리오 건수, 파일 무결성 검증 결과, 권한/인증으로 미도출된 항목**을 보고한다.
